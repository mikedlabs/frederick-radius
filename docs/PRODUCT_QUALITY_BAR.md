# Product quality floor

The owner's target is at least 8/10 for every part of Frederick Radius, not an
average that lets a strong landing page hide a weak map or search journey.
This is a product-review target, not a score generated by passing tests.

## What an 8 must demonstrate

| Area | Minimum evidence |
| --- | --- |
| Visual design | Clear reading order, one primary action, consistent Radius type and colors, and reviewed real screenshots. |
| Usability | A common need reaches a useful answer within two actions after location setup. No dead-end results or unexplained handoffs. |
| Navigation | Today, Map, Events, and Saved remain predictable. Search area, filters, selection, and Back behavior agree. |
| Content and trust | Current source-backed facts; explicit unknowns; no invented hours, map positions, or appointment times. Partial feeds are not presented as no events. |
| Mobile and access | Usable at 320, 375, 390, and 430 pixels, with readable labels, keyboard/focus recovery, 44-pixel targets, and no WCAG A/AA violations. |
| Reliability | Rendering, interaction, data-health, and deployed revision checks pass independently. A green deployment alone is insufficient. |

## Scope

Review the primary journeys first: Today, Find/Search, county Map, Events,
place and event details, Ask, and Saved. Then review the tool and guide routes
covered by `scripts/page-quality-audit.ts`. Include the Fair as its own
connected journey. Shared-template checks do not certify every listing's
content.

## Repeatable checks

- `npm run test:quality` checks the small-screen and desktop core navigation,
  Today's first-screen request doorway, and the corrected search-area journey.
- `npm run test:ux` checks rendering and WCAG A/AA across key public surfaces.
- `npm run test:visual:capture` produces Find, Ask, and map review candidates.
  Follow `docs/VISUAL_CONTRACT.md`; captures are not automatically approved.
- Type checking, ESLint, unit tests, voice, color, and stacking checks remain
  required before a commit. Shared primitives also require Storybook checks.
- The normal release path verifies required GitHub checks, the exact production
  revision, the production audit, and the changed behavior on the public site.

## Known limits, not passing scores

The Fair booth explorer uses the reviewed September 21, 2026 snapshot of all
three official layout sections: 155 exhibitors and 511 booth shapes. Owner
permission is recorded in the release manifest. These are source-layout
coordinates, not surveyed GPS positions or walking routes. A booth listing
does not confirm today's hours or inventory. Rich menus and saved vendor stops
remain limited to the separately reviewed vendor profiles; the complete booth
directory does not imply equivalent editorial detail for every exhibitor.

Provider coverage, performance, assistive-technology behavior, and editorial
completeness need their own evidence. Never mark these 8/10 merely because the
page renders or automated tests pass. Record unreviewed areas as unreviewed.
