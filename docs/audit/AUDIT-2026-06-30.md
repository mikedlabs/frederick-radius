# Frederick Radius — Site Audit Report

## Executive summary

This audit covered the full surface of Frederick Radius: the map, the /today briefing, events (list, detail, calendar, agenda), places, the intent pages (/plan, /deals, /nearby, /search, /happy-hour, /brunch), municipality and outdoors pages, transit, pulse, the from-above/aerial features, onboarding/auth, settings, submit/business flows, the marketing /pitch deck, admin, the data pipeline, SEO/metadata, PWA service worker, RSC payloads, and the design-token system.

The app is in good structural health — the architecture described in CLAUDE.md (unified event assembly, boundary cleaning, closed place set, audited canonicals) is largely intact and the code is unusually well-commented about its own intent. The problems cluster in three places: **(1) a handful of high-impact features that are silently broken end-to-end** (map search dropdown, parks/trails "tap to see on map," the aerial time-machine scrubber, the notifications opt-in default); **(2) a stored-XSS hole in feed-derived JSON-LD**; and **(3) pervasive design-token drift** — the brand palette was refreshed (brick→Signal vermilion, old gold→Almanac gold, old cool→new cool, old green→Spruce) but ~27 brick literals, ~9 old-gold literals, four copy-pasted town-accent arrays, and 1,476 ad-hoc `text-[Npx]` literals never followed, so live UI renders the *pre-refresh* brand in places.

A recurring meta-theme: **several of these defects are self-documented** — the code's own comments promise behavior the code does not deliver (the aerial base-layer comment, the all-day "never a bare 12:00 AM" comment, NowIntel's `/pulse#weather` comment, the weekend page's "no in-app linker" comment, the transit "GTFS isn't published yet" footer, the admin "public, unauthenticated" note). These are the cheapest, highest-trust wins because the intent is already written down; only the wiring drifted.

Counts: **1 P0 (security), 7 P1 (broken core features + SEO + a11y), ~28 P2, ~30 P3.** Most fixes are small and local.

### What is healthy (so this reads balanced)
- **Boundary-cleaning architecture is sound.** `normalize.ts`, `placeName.ts`, the unified event assembly, and the overrides/dedup layering are the right design; the defects below are gaps *within* that design (a feed flag not threaded, two fold layers misaligned), not the design being wrong.
- **Canonical/SEO discipline mostly held.** The audited routes (today, live-music, deals, collections) correctly self-canonicalize; the misses (/plan, /nearby, /search, folded place aliases) are the exceptions, and they're one-line additions.
- **The token system itself is correct and complete** — `globals.css` ships AA-safe `*-press` variants, an `--app-on-brand` warm near-white, a canonical type scale, and tints. The problem is purely *adoption*: consumers drifted, not the tokens.
- **The code documents its own intent well.** Almost every defect was findable *because* a comment stated the contract; that culture is an asset and makes the cleanup batches low-risk.

## P0 — Critical (security)

### Security
- **Stored XSS via feed-derived JSON-LD** — `src/app/(app)/events/[slug]/page.tsx:687` (and `places/[slug]/page.tsx:519`, `m/[municipality]/page.tsx:160`, events-list `page.tsx:327`, `category/[slug]/page.tsx:176`). Bare `JSON.stringify(jsonLd)` into `dangerouslySetInnerHTML` does not escape `<`/`>`/`&`; a `</script` substring in any feed field (title, blurb, venue, organizer) breaks out of the script element and executes. `cleanFeedText` does **not** neutralize this (it decodes `&lt;`→`<` and only strips *balanced* tags), confirmed by repro. **Fix:** add `jsonLdScript(obj)` to `src/lib/seo/jsonld.ts` (already exists, currently only has breadcrumb/itemList helpers) that runs `JSON.stringify` then `.replace(/</g,'\\u003c').replace(/>/g,'\\u003e').replace(/&/g,'\\u0026')` (+ U+2028/2029), and route all five emits through it.

## P1 — High (broken core features, SEO consolidation, AA contrast on primary controls)

### Feature-broken (primary user paths that silently do nothing)
- **Map "Search this map" dropdown never appears** — `src/components/map/AppMapDeck.tsx:224`. The results `<ul>` (`absolute … top-full`) lives inside a pill that has `overflow-hidden` (`AppMapDeck.tsx:176`), which clips any absolutely-positioned descendant. The map's primary search produces matches the user can never see. **Fix:** render the `<ul>` as a sibling of the pill inside an outer `relative flex-1` wrapper (mirror `LocationAutocomplete.tsx`), or drop `overflow-hidden` from the pill.
- **Every park/trail row links to `/map?focus=lat,lng`, a param the map never reads** — `src/app/(app)/parks/page.tsx:42`, `src/app/(app)/trails/page.tsx:43`. Verified: `map/page.tsx:242-255` searchParams are `{ intent, sub, t, open, mode }` — no `focus`/`at`; `AppMap`'s `focus` prop is a `{slug,n}` set only by in-map taps. The page literally says "Tap one to see it on the map." **Fix:** add an `at?: string` coord param to the map page, parse `"lat,lng"` and fly the camera on mount; update parks/trails rows + the `Row.tsx:21` JSDoc example.
- **Aerial time-machine scrubber is non-functional** — `src/components/from-above/AerialTimeMachine.tsx:86`. `opacity = year===activeYear ? 1 : isBase ? 1 : 0`; the base (newest 2025) year is *last* in `AERIAL_YEARS` so Mapbox stacks it on top, always at opacity 1, hiding whatever historical year you scrub to. The comment at line 81-83 even claims the base "sits at the bottom" — it does not. **Fix:** mount the base first / use `beforeId` so active years stack above it, or gate `isBase` opacity to `activeYear === baseYear`.
- **Notifications opt-in enrolls the user in all 5 topics on first subscribe** — `src/components/settings/NotificationsCard.tsx:36`. State seeds `new Set(ALL_TOPICS)` and the per-topic buttons are `disabled` until *after* subscribing, so the first "Turn on" POSTs all five — directly contradicting the subpage copy "Topics are off until you turn them on." **Fix:** seed `new Set()` (or a single `civic-alerts` default), or enable the toggles before subscribe.

### Feature-broken (collision / overlap)
- **Expand badge and Save button collide on the place sheet** — `src/components/place/PlaceSheet.tsx:297`. The zoom/Expand glyph (`right-3 top-3 z-10`) and the SaveButton wrapper (`right-3 top-3`, no z-index) occupy the same corner whenever a hero image exists (the common enriched case); a corner tap is ambiguous. **Fix:** anchor them apart (Save top-left or offset down) with explicit z-order; `pointer-events-none` on the decorative Expand span.

### SEO (duplicate-indexing / equity loss)
- **Folded place aliases self-canonicalize to the alias** — `src/app/(app)/places/[slug]/page.tsx:127`. `canonical: /places/${slug}` uses the URL param, not the resolved `place.slug`, so `/places/carroll-creek-linear-park` (a fold alias returning 200) canonicalizes to itself instead of the canonical record — the fold never consolidates. The same page's BreadcrumbList (`:530`) correctly uses `place.slug`, so it contradicts itself. **Fix:** `canonical: /places/${place.slug}`; better, 308-redirect when `slug !== place.slug` like events/[slug] does.

### A11y (AA failure on a primary inline link)
- **Inline body link in `--app-brand` fails AA (3.24:1)** — `src/app/(app)/markers/page.tsx:116`. `#E14328` on the cream ground is 3.24:1 for 14px text, and there's no underline, so color is the only affordance. The token block already ships `--app-brand-press` (#B5300F, 4.80:1) labeled "text-on-light." **Fix:** use `var(--app-brand-press)` and/or add a persistent underline.

## P2 — Medium

### Data honesty (wrong values reach the user)
- **All-day events render "12:00 AM" everywhere; the null-time guards are dead code** — `src/lib/loaders/events.ts:451`. `eventDateBlock()` formats `starts_at` unconditionally and never checks `is_all_day`, so `date.time` is always truthy and the card guards (`EventCard.tsx` glance/compact/feature, `EventAgenda.tsx:111`) never fire — the comment promising "never a bare 12:00 AM" is unreachable. **Fix:** return `time:""` when `e.is_all_day`; render "All day" in EventAgenda; guard the compact span.
- **All-day iCal events render one day early at a fabricated 8 PM** — `src/lib/loaders/liveEvents.ts:66`. `parseICalDate` returns UTC-midnight for VALUE=DATE but no all-day flag is threaded; `liveToCardEvent` hardcodes `is_all_day:false`, so the instant renders as 8 PM the *previous* ET day. **Fix:** thread `allDay` from `parseICalDate`→`ParsedVEvent`→`LiveEvent`→`liveToCardEvent`, and anchor all-day rows at Eastern noon via `easternWallToUtcISO`.
- **`hasImplausibleStartTime` can't catch the all-day shift** — `src/lib/events/visible.ts:72`. Because all-day rows arrive at ET hour 20 with `is_all_day=false`, both the `is_all_day` early-return and the `h<9` test are bypassed, so a wrong-day arts/theater festival publishes. **Fix:** the iCal-boundary fix above is the root cause; optionally treat ET-midnight in these categories as suspect.
- **/deals shows a multi-day deal's other-day prices under the wrong day** — `src/lib/loaders/todaysDeals.ts:295`. `allDeals()` builds one row from the full raw text (`days=[2,3,4]`) instead of splitting per-day like `todaysDeals()` does; tapping "Tuesday" shows Wed/Thu prices too. **Fix:** emit one row per named day, narrowed with `todayClause(raw,d)` + `readsAsOffer`.
- **TAG / The Artists Gallery erased from every public surface** — `src/data/places-overrides.json:18`. The overrides fold (`tagthe-artists-gallery → -frederick`) and `places-dedup.json` (`-frederick → tagthe-artists-gallery`) fold into each other; `publicPlaces()` confirms *both* slugs absent. A valid Downtown Frederick gallery is invisible on map/search/town/sitemap. **Fix:** align the two layers on one canonical, then `npm run build:client-places`.

### Feature-broken
- **Live calendar events dead-end at `href:"#"`** — `src/lib/loaders/calendar.ts:109`. Live-feed rows are pushed with hardcoded `"#"` though they have real `/events/<liveCleanSlug>` detail pages; in MonthGrid they look clickable but do nothing. **Fix:** `href: /events/${liveCleanSlug(e)}`.
- **Town "Search {town}…" pill routes to the global /search landing, unscoped** — `src/app/(app)/m/[municipality]/page.tsx:222`. `href="/search"` (no params) lands the user on the generic empty prompt screen despite the town-scoped label/aria. The "All places in {town}" link 8 lines down does it right (`/search?q=${name}`). **Fix:** point the pill at `/search?q=${encodeURIComponent(m.name)}`.
- **Search prompts deep-link to `?t=` that /today ignores** — `src/app/(app)/search/page.tsx:123` (+ `TimeToggle.tsx:50`, `SearchOverlay.tsx:550`). `HomePage()` takes no searchParams and TodayTabs ignores `?t=`, so "What's on this weekend" → `/today?t=weekend` resolves to the default tab. **Fix:** have /today read+validate `searchParams.t`, or repoint weekend links at `/events`; fix TimeToggle's false comment.
- **Magic-link error silently swallowed** — `src/app/auth/login/page.tsx:31`. The callback bounces to `?error=expired|missing_code` but LoginPage never reads `error`, so an expired link shows a pristine form with no explanation. **Fix:** read `error`, render a `role="alert"` message above LoginForm.
- **Power tile fires an empty "situation" for unincorporated outages** — `src/app/(app)/pulse/page.tsx:229`. `total_out` is the county rollup but `munis` is filtered to incorporated towns; a real outage in unincorporated county yields `outagesActive` with `munis=[]`, so the tile turns red with zero detail rows and no peek. **Fix:** when `munis.length===0`, set peek from the county total and render a county row.

### Security
- **Open redirect on logged-in `next`** — `src/app/auth/login/page.tsx:36`. `redirect(sp.next || "/my-radius")` is unvalidated, so `?next=https://evil.com` 302s a signed-in user off-site. /beta and the callback already guard this. **Fix:** `safeNext = next.startsWith("/") && !next.startsWith("//") ? next : "/my-radius"`.
- **Callback `next` allows protocol-relative redirect** *(worth a look — same class)* — `src/app/auth/callback/route.ts:62`. `safeNext` only checks `startsWith("/")`, so `//evil.com` resolves off-site. **Fix:** add `&& !next.startsWith("//")`.
