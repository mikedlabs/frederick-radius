# Security

Frederick Radius welcomes responsible reports that help protect visitors and the project.

## Report privately

Do not open a public issue for a suspected vulnerability. Email **hello@frederickradius.app** with the subject `Security report`.

Include, when possible:

- the affected page or feature;
- a concise description of the issue and likely impact;
- safe reproduction steps;
- the browser, device, and approximate time observed; and
- screenshots or a minimal proof of concept with credentials and personal information removed.

Never include passwords, API tokens, session values, private user data, or data belonging to another person. If the exposed secret belongs to you, revoke it before sending the report.

## Safe research

Please avoid:

- accessing, changing, deleting, or retaining another person's data;
- disrupting the service, sending high-volume traffic, or testing denial of service;
- social engineering, physical attacks, or attacks on third-party providers;
- automated scanning that ignores rate limits or published restrictions; and
- public disclosure before Frederick Radius has had a reasonable opportunity to investigate.

Stop testing and report the issue if you encounter private data or gain unintended access.

## What happens next

Frederick Radius will confirm receipt when practical, assess the report, and share updates when there is a meaningful change. This is a small independent project, so response times are not guaranteed. There is no bug-bounty or paid-reward program.

This public hub contains no production source, secrets, private infrastructure, or deployment configuration. Reports about GitHub itself or another provider should be sent to that provider unless the issue is caused by Frederick Radius.
