# Frederick Radius - Live Site Review

**Reviewed:** 2026-07-08 against the live private-beta site.  
**Lens:** product usefulness, first impression, mobile ergonomics, trust signals, and live-data credibility.  
**Companion audit:** `docs/audits/2026-07-08-site-audit.md`.

## Thesis

Frederick Radius has crossed the line from "promising idea" to "credible local utility." The strongest version of the product is not the pitch language; it is the app itself: `/today`, search, map, events, county services, and trust/source pages together feel like an operating layer for Frederick County.

The main work now is trust polish. A local app lives or dies on whether users believe the live labels, open-now states, event timing, map pins, and photos. When Frederick Radius is right, it feels unusually useful. When it shows stale loading copy, an overbroad "Live" label, or a blank media well, the entire promise gets softer.

## What is working

- **`/today` is the product.** Weather, "on now", open-now places, intent tiles, town scope, and live events are all on one screen without feeling like a generic directory.
- **Search is genuinely useful.** Querying `pizza` returned a tight local set with category, town, confirmation state, and photos on mobile. It feels like command-palette search for the county.
- **The visual language is distinctive.** The editorial typography, plate/specimen language, tactile cards, and warm map style give the app an identity that local directory products usually lack.
- **Trust pages are unusually strong.** `/trust` explains sources and badges clearly. `/about` says what the product is not, which helps people understand what it is.
- **County services is a hidden strength.** `/contacts` is practical, civic, and likely to create repeat usage outside restaurant/event discovery.

## Highest-priority issues

### P0.1 Make live status labels stricter

The sampled event detail showed `Reading of the Declaration of Independence at Catoctin Furnace` as `12:00 PM-11:59 PM Live`. That looks like an imported all-day or long-window listing being treated as actively live. This is the kind of detail users will remember if it is wrong.

**Fix:** split status into explicit states:

- `Live now` only when current time is inside a credible start/end window for a real-time event.
- `Today` for all-day or date-only feed items.
- `Starts soon`, `Ended`, and `Ongoing exhibit/season` for long-running cases.

### P0.2 Make loading states tell the truth

`/map` still displayed "Loading public places from OpenStreetMap..." after markers, filters, and counts were visible. The route may be partially loaded, but the copy tells the user the page is still waiting.

**Fix:** replace route-level loading copy with staged labels: `Map ready`, `Adding public amenities`, `Some public layers still loading`, or remove the label after the first marker layer paints.

### P0.3 Stop large blank media wells

Events and place pages are polished when images load. When they do not, they expose large blank or empty-thumbnail areas. Rosati's still showed failed visible thumbnails after settling, and desktop events had a large failed event image.

**Fix:** use category/town fallback art, collapse failed thumbnails, and cap the height of media placeholders until an image is confirmed.

## Product sequencing

1. **Correctness pass:** live labels, loading states, stale feed windows, source badges.
2. **Media fallback pass:** event hero fallback, place gallery fallback, search thumbnail fallback.
3. **Mobile overflow pass:** `/events` controls and bottom-nav occlusion at 390px.
4. **Discovery pass:** surface `/contacts`, `/trust`, and saved starter actions from `/today`.
5. **Only then add more feeds/widgets.** The site already has enough breadth; the current win is making existing surfaces feel unambiguously reliable.

## Bottom line

The site is compelling because it is opinionated and useful at the same time. Do not sand off the personality. Tighten the places where the machine says something live, current, open, confirmed, or loaded. Those words are the contract.
